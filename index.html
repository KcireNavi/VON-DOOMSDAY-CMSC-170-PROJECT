Problem statement and motivation

The task is to predict whether a landslide event is fatal from its category, trigger, size, setting, location accuracy, location and month.

Landslides kill people and destroy homes and roads. Identifying quickly which reported events are likely to be fatal could help responders decide where to send resources first, as in a decision support system for early severity assessment.

Dataset

Source
NASA Global Landslide Catalog.
Size
9,648 events after dropping rows with a blank fatality_count. The experiments use a random sample of 6,000 of these, of which 1,526 (25.4%) are fatal.
Target
fatal = 1 if fatality_count > 0, otherwise 0. Fatal is the positive class.
Features
9 in total: landslide_category, landslide_trigger, landslide_size, landslide_setting, location_accuracy, latitude, longitude, month, logpop.

Preprocessing

Rows with a blank fatality_count were dropped. Blank categorical values were set to “unknown” and one-hot encoded, with an extra column for categories not seen in training. Blank numeric values were filled with the training median, and all numeric features were standardized. month comes from event_date, and logpop is the log of 1 plus the administrative division population.

Medians, means, standard deviations and category lists are learned from each fold’s training portion only. All of this is done with the csv module and NumPy.

Methods

All three methods are implemented from scratch with Python and NumPy.

Naive Bayes

How it works and how we implemented it: every feature is treated as categorical. Latitude, longitude, month and logpop are cut into 10 bins at training quantiles, and the one-hot columns stay 0 or 1. For each class, the method estimates how often each feature value occurs, using smoothing of 0.1 so unseen values do not give zero probability, and multiplies these with the class prior. An event is flagged fatal when its fatal probability reaches the cutoff.

Why we chose it: a fast probabilistic method that works well with the one-hot encoded categorical features such as landslide category, trigger and size.

k-nearest neighbors

How it works and how we implemented it: the method measures the Euclidean distance from an event to every training event, and the k nearest events vote. Because fatal events are rarer, each fatal vote counts as many votes as the ratio of non-fatal to fatal training events, so fatal neighbors are not outvoted. Ties go to the closest neighbor.

Why we chose it: it makes no assumptions about the data and tests whether landslides with similar characteristics and nearby locations tend to share the same outcome.

Decision tree

How it works and how we implemented it: the tree repeatedly splits the data on one feature and threshold, choosing the split with the largest drop in Gini impurity, until the depth limit or the minimum sample sizes are reached. Each leaf predicts its majority class. Fatal events are duplicated in the training data until both classes are the same size.

Why we chose it: it captures combinations of features, such as a large landslide in a populated area, and its rules are easy to read.

Experimental setup

Data splits
3-fold cross-validation on a random shuffle (not stratified, seed 42). Each fold is tested once on data not used for training.
Metrics
Accuracy, precision, recall and F1 (implemented from scratch). Recall matters because a missed fatal landslide is costly. Metrics are averaged over the folds.
Cost
Each false positive counts as 1 and each false negative as 2, so a missed fatal landslide is twice as bad as a false alarm. Cost is summed over the folds; lower is better. The weights are our assumption.
Hyperparameters
Chosen separately in each fold. The training portion is split 80/20, and the candidate with the lowest cost on the 20% is kept. The model is then retrained on the full training portion and tested on the held-out fold.

Comparison of all methods

How to read the metrics

Fatal landslide is the positive class.

Precision
Of all landslides flagged as fatal, the share that were truly fatal. It shows how much response effort goes to real threats instead of false alarms.
Recall
Of all truly fatal landslides, the share the system flags. It shows how many deadly events are caught for early assessment.
TP
A fatal landslide correctly flagged, so response resources can be prioritized early.
TN
A non-fatal landslide correctly left unflagged, so no resources are diverted unnecessarily.
FP
A non-fatal landslide flagged as fatal, causing a false alarm and wasted resources.
FN
A fatal landslide the system missed. This is the costliest error, because a deadly event gets no priority response.

Discussion

Why the methods performed as they did

  • Baseline: its accuracy equals the share of non-fatal events (74.6%), but it never flags a fatal landslide, so recall and F1 are 0. This is why accuracy alone is misleading here.
  • All three models: they were tuned for cost, which penalizes misses, so they flag many more events. Their accuracy (0.740 to 0.755) stays close to the baseline while recall rises to between 0.80 and 0.91.
  • Naive Bayes: it assumes the features are independent, but trigger, category, size and setting are related. This likely makes its probabilities overconfident and contributes to its 1,339 false alarms.
  • k-nearest neighbors: it had the fewest false alarms (1,158) and the most misses (312) of the three. The many one-hot columns may dominate the distance, so the nearest events are not always truly similar.
  • Decision tree: it missed the fewest fatal landslides (136). It was trained on balanced data and chooses the most informative features itself.
  • Precision: it is about 0.49 to 0.51 for every model, which suggests these features only partly explain whether a landslide is fatal.

Limitations

  • Folds are random. Events from the same storm can fall in both training and test data, which may inflate scores.
  • The experiments use a 6,000-event sample of the 9,648 events.
  • The cost weights (1 and 2) are an assumption, and the hyperparameter grids are small.

Possible improvements

  • Use time-ordered or grouped folds so test events come from later or different storms.
  • Repeat the experiment with several seeds and report the spread.
  • Run on all 9,648 events and test other cost weights and cutoffs.

Conclusion

The decision tree worked best under the cost used here (false positive 1, false negative 2). It had the lowest cost (1,699), the highest recall (0.911) and the highest F1 (0.640), and it missed 136 fatal landslides. The k-nearest neighbors method had the best accuracy and precision.

The margins between models are small, and every model’s precision is about 0.5, so roughly half of its flags are false alarms. The features alone do not separate fatal from non-fatal events well.
